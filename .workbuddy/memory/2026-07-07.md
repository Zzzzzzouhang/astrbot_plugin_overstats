### 拆分关键技术点
- 每个 mixin 文件复制原 `main.py` 导入块（1-51 行，含 `from astrbot.api.all import *` 提供的 `Star`/`register`/`Context`/`AstrBotConfig` 等），用 `try/except` 同时支持相对导入与顶层导入。
- 用 `ast` 解析类体、按**方法单元**（装饰器+def 整体）切分，避免装饰器被切断到相邻文件（第一版脚本按行范围切分导致此 bug）。
- `OverstatsPlugin` 仅 `pass`，所有逻辑在 mixin；astrbot 经 MRO 遍历收集 `@filter.command`，注册行为零改动。

### 验证方式（重要）
用桩模块模拟 astrbot 环境（`astrbot`/`deploy`/`aiohttp` 占位，含 `filter.PlatformAdapterType` 用 `enum.Flag` 以支持 `|`），`importlib` 加载 `main.py` 后 `inspect.getmembers` 收集：
- MRO 合法：`[OverstatsPlugin, Star, PluginCore, PluginBinds, PluginEvents, PluginCmdsQuery, PluginCmdsBrowse, PluginCmdsAdmin, object]`
- 55 个 `@filter.command` 全部收集，无方法遗漏（missing 为空集）。

### ⚠️ 事故与恢复
拆分过程中第一轮脚本误把已含 error_code 的 `main.py` 覆写为 26 行壳，并第二轮把含 error_code 的 mixin 也覆盖为桩，导致 **error_code 改造丢失且无 git 备份**（HEAD 不含该改动，`.pyc` 为 6/24 旧版）。
恢复步骤：从 HEAD `git checkout main.py`（3448 行，无 error_code）→ 重新应用 error_code 改造（脚本化：_fetch_image 三元组 + 25 处调用点解包 + 24 处 err_code 声明 + 24 处 finalize 透传 + def 签名 + 内部 record_command）→ 重新加 monitor API 时间范围与 failures 端点 → 再干净拆分。
教训：**拆分脚本运行前必须先备份原文件**（如 `cp main.py main.py.bak`），且行范围切分务必按方法边界而非裸行号。
